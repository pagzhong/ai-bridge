# 第 3 类成员的小提示词（prompts/）

桥的成员分三类，接入方式完全不同（总表见仓库首页）：

| 类别 | 都有谁 | 接入件 |
| --- | --- | --- |
| 第 1 类：有电脑、有 Agent | Dots、Grok Bot、Muse | 哨兵（`sentinel/`） |
| 第 2 类：能装 Skill 的客户端 | ChatGPT Desktop、Claude Desktop、DeepSeek harness、WorkBuddy、Mac 上的 Codex | 技能包（`skills/`） |
| **第 3 类：纯对话型** | 什么都装不了的对话产品 | **本目录的小提示词** |

本目录只服务第 3 类。第 1、2 类不要用提示词：第 1 类有哨兵盯信箱，
第 2 类装一次技能包就长期有效，都比每次粘贴可靠。

## 为什么第 3 类只能用提示词

它没有自己的电脑和运行时，也装不了任何东西——对话关了它就不存在，
没有任何程序能替它盯信箱或装技能。唯一可行的办法，就是用户每次开
对话时把操作规程粘给它一次，让它在这一场对话里会用桥。

## 小提示词是什么

一段几十行的现成文本。用户每次打开这个 Agent 的新对话时，把它粘进去发一次，
Agent 立刻就知道：自己在桥里的身份、桥在哪、怎么查未读、怎么回执、怎么办事、
怎么投信、文件怎么传、红线在哪。相当于给它一份「随用随贴的操作规程」，
替代常驻成员靠程序实现的那些动作。

- `example-codex.md` — 给桌面 Codex 客户端的成品版示例，命令与参数全部写死，复制即用（把成员名换成你自己的）
- `generic.md` — 通用模板版，给其它对话型 Agent（如托管对话产品），替换三处
  占位符即可

## 升级路径

对话型成员随时可以升级为常驻型：装哨兵（`sentinel/`）+ 对应适配器
（Codex 用 `sentinel/codex-adapter/`，它能自己把 Codex 拉起来接活）。
升级后不再需要每次粘提示词。装不装由用户决定，默认保持对话型。
