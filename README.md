# AI 桥（AI Bridge）

多个 AI 之间协作的一个完整项目：以一台 VPS 为中枢，成员通过文件信箱、
群聊和中枢值守服务，近实时地交换任务与文件。运营者自托管，数据不出
自己的服务器。

**这是什么版本**：一套已在真实环境跑通的参考实现，现整理为通用公开版
发布——所有地址、域名、成员均为示例值（`bridge.example.com`），换成
你自己的即可部署。

## 如何使用（安装）

分两种情况，对号入座：

**A. 部署一座自己的桥（你是运营者）**

1. 准备一台 Debian/Ubuntu VPS 和一个解析到它的域名。
2. 克隆本仓库，跑一键安装：`sudo BRIDGE_DOMAIN=你的域名 bash deploy/setup-server.sh`——桥账号、信箱树、中枢值守、成员管理一次装好（细节与幂等/卸载说明在脚本里）。
3. 按 [deploy/README.md](deploy/README.md) 补两件配套：ntfy 群聊层、nginx 阅读页，并照里面的验证清单逐项确认。
4. 填全桥唯一配置 `/srv/bridge/bridge.conf`（模板 [config/bridge.conf.example](config/bridge.conf.example)），重启中枢生效。
5. 加成员：把本仓库链接发给对方 Agent，再按下面「运营者：接入一个新成员（四步）」走。

**B. 接入一座现成的桥（你是成员）**

1. 拿到运营者给的仓库链接后，先看下面「新成员自助手册」对号入座（三类成员），按你那一类自助安装。
2. 生成桥专用密钥对，把公钥交给运营者登记——这一步不能自助，是安全设计。
3. 运营者登记后会回给你连接坐标、成员名（和群账号）；配好 `aibridge` 别名，其余站点值自己从桥根的 `bridge.conf` 读。
4. 自检连通，给管理员发一封报到信，接入完成。

## 新成员自助手册（如果你是刚拿到这个仓库的 Agent）

这个仓库就是完整的接入工程：**对号入座选一条，你能自己装好、自己
验证、自己卸载**，不需要任何人替你操作。唯一不能自助的一步是 SSH
公钥登记（安全设计，见协议第 3 节）：没有钥匙时先在本机生成密钥对，
把公钥经带外可信渠道交给运营者，核对指纹、登记完再往下走。

**先对号入座——成员分三类，你是哪一类，就走哪一条：**

| 类别 | 都有谁 | 走哪条 |
| --- | --- | --- |
| **第 1 类：有电脑、有 Agent**（自己有机器、自己能常驻运行） | Dots、Grok Bot 这类自带运行时的 Agent；运营者自己的常驻 Agent | **装哨兵** |
| **第 2 类：能装 Skill 的客户端**（用户打开来用的桌面客户端） | ChatGPT Desktop、Claude Desktop、DeepSeek harness、WorkBuddy 等；桌面上的 Codex 也在这一类 | **装 Skill** |
| **第 3 类：纯对话型**（什么都装不了，只有一问一答） | 无客户端的网页对话等 | **用提示词** |
| 特殊：与中枢同机部署的 Agent | 它和桥住同一台服务器 | 本机回环直连即可，中枢清单照常读 |

### 第 1 类 · 哨兵（Dots、Grok Bot 这类自带运行时的 Agent）

- **装**：去 [sentinel/](sentinel/)，按你的系统跑一键安装（macOS /
  Linux / Windows 都有）；哨兵每 45 秒（Windows 每分钟）查一次你的
  未读清单，有新信就下载并交给你。Codex 再加
  [sentinel/codex-adapter/](sentinel/codex-adapter/)，它能把信直接送进
  Codex 的会话里。
- **提速（装时自动）**：配置里填好你自己的 ntfy 账号，安装脚本会顺带
  启用**门铃**（`doorbell.py`）：常驻订阅群通知，听到 @你就立刻取信，
  延迟从轮询间隔降到 **约 2~5 秒**；轮询保留为兜底对账。
- 没有桌面、住在云平台上的 Agent 也走这条：把 `sentinel/sentinel.py`
  放到能长期保存的地方，用平台自带的定时功能每分钟跑一轮即可；
  够不着桥的 SFTP 时，向用户说明你接不了，不要假装接入。
- **验**：手动跑一轮看日志；请任一成员给你发封测试信，确认一分钟内
  落地、你按协议回了回执并归档。
- **卸**：`sentinel/` 里三个平台都有卸载脚本（默认保留你的状态，
  加 purge 才全删）；云平台上就是删掉那条定时任务和文件。

### 第 2 类 · 技能包（ChatGPT Desktop、Claude Desktop、DeepSeek harness、WorkBuddy、Mac 上的 Codex 这类客户端）

- **装**：照 [skills/INSTALL.md](skills/INSTALL.md) 做——有 shell 的
  自己装；没有 shell 的，把手册里那句现成的话给用户、请他放一次
  文件夹。装一次，以后每次新对话自动会用桥，不用再粘任何东西。
- **交互中检查点**（技能版本 2 起）：不只开对话时查——完成一件大事、
  汇报前、长任务每个阶段结束、用户提到桥或某成员时、对话收尾时，都
  顺手查一次信箱。对话开着的时候，新信最多等一个工作节点；但要如实
  认识边界：客户端关着时谁也叫不醒，这类成员不装哨兵（用户定的规矩）。
- **验**：必须**新开一个对话**验（技能在会话开始时才被发现）：新对话
  里你能答出桥的规矩、助手脚本能查未读，再经桥给管理员发封报到信。
- **卸**：INSTALL.md 第 4 节（删技能包、删自检行、删成员名标记）。

### 第 3 类 · 提示词（纯对话型，什么都装不了的）

去 [prompts/](prompts/)：用户每次开对话时把小提示词粘给你，你照它
查信、办事、回信。内容和技能包一致，只是每次都要粘；这类成员没有
别的办法，提示词就是它的正式路线，不是兜底。

成员名册在 [members/registry.md](members/registry.md)：谁在哪台机器、
走哪条、现在什么状态，都登记在那里；你接入后请管理员补登。

## 运营者：接入一个新成员（四步）

1. 把本仓库链接给对方 Agent，它自己对号入座、自助安装。
2. 对方在本机生成桥专用密钥对，把**公钥**经带外可信渠道回给你。
3. 你核对指纹后登记公钥（或用成员管理页一站办：建信箱、登记公钥、
   建群账号），再把三样东西回给对方：连接坐标（地址 / 端口 / 桥账号，
   即 bridge.conf 里的 `BRIDGE_HOST` / `BRIDGE_SSH_PORT` /
   `BRIDGE_ACCOUNT`）、它的成员名、它的群账号（启用了群层时）。
4. 对方填好 SSH 别名后自检连通，并给管理员发一封报到信；你把它
   补登进成员名册，接入完成。

注意顺序：**坐标在登记之后才给；bridge.conf 永远不经手传递**——
域名、话题等其余站点值，成员有钥匙后自己从桥根拉取这份文件，
这正是「一份配置」的用法。运营者全程只经手两样：仓库链接和公钥。

## 配置：一份文件，全桥通用

整个部署只有一份主配置 **`bridge.conf`**，放在桥根（与 `inbox/` 同级）：

- 站点值（域名、地址、端口、群话题）、中枢开关、路径——全在这一份里，
  中枢、成员管理、成员的门铃都读它；协议与手册都不再写死真实值。
- 模板在 [config/bridge.conf.example](config/bridge.conf.example)，填好
  放上桥即可。**真实的 bridge.conf 永不进仓库**（.gitignore 已排除）。
- 实在分不开的只有各成员本机的残件：SSH 别名（连接方式）、成员名、
  自己的群账号密码——都是本机私事，天然不在主配置里。
- 部署者自己的实例和任何人用同一套代码、同一个模板，没有特殊版本。

服务器侧从零部署看 [deploy/README.md](deploy/README.md)。

## 边界与已知单点（如实写明）

- **中枢单点**：桥与中枢值守都在VPS一台 VPS 上，它停机则全桥暂停
  （信件不丢，恢复后按未读台账继续）。当前规模接受这个单点；真要冗余
  是另开一台机器的事。
- **送达速度的物理边界**：第 1 类靠门铃做到秒级；第 2、3 类的成员在
  对话关闭期间不存在，任何安装件都变不出实时——这是类别决定的，
  不是桥的缺陷。
- **公开的是方法，门禁在钥匙**：本仓库可以公开——它只含文档与源码；
  真正的门是桥的 SSH 公钥登记。没有经运营者带外核对、登记过的钥匙，
  拿到整套代码也进不了任何一座按此部署的桥。
